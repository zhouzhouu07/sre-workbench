# 首次使用与运维说明

任务助手使用 OpenAI 兼容模型时要求支持 `response_format: {"type":"json_object"}`，以保证工具响应为合法 JSON。不支持该参数的服务可能返回 HTTP 400；请使用支持 JSON 输出的模型接口，或选用 Anthropic 兼容协议。脚本助手兼容入口不要求该参数。

Anthropic 兼容任务助手使用原生 `submit_step` 工具调用，接口需支持 `tools` 与指定 `tool_choice`。该请求关闭思考模式，避免与强制工具调用冲突；一次仅接受一个结构化步骤，仍由后端校验参数与权限。DeepSeek 的 `deepseek-flash` 与 `/anthropic` 已通过真实多轮环境检查。

## 主机连接

使用 root 或具有 sudo 权限的普通账号。密码和私钥由 Windows 系统加密后保存在本机 SQLite；编辑时留空保留现有凭据。私钥可粘贴 OpenSSH/PEM 内容，带口令的密钥另填口令。

首次连接需要核对 SSH 公钥指纹。指纹变化会拒绝连接；核实服务器重装或密钥变更后，删除并重新建立主机配置。主机删除不会删除服务器文件。

非 root 用户执行不使用 sudo 的长脚本时，需要管理员预先启用该用户的 systemd lingering，并确保 `systemctl --user` 可用。否则可明确选择 sudo 执行。主机必须以 systemd 作为 PID 1。

## 部署向导

点击「部署」或「回退」后，先查看环境检查表。系统、权限、工具、磁盘、端口等阻塞项必须解决后才能确认执行；Docker 待安装、可用内存偏低、SELinux 和防火墙策略以提示显示。可点击「重新检查环境」刷新结果。正式执行前后端会再次检查，防止检查后环境变化。预检本身不安装软件、不修改防火墙，也不能保证外部镜像仓库和构建依赖始终可达。

确认部署后会按需安装 Docker，并启动及启用 Docker 开机自启，使已部署的容器能够在服务器重启后恢复。

远端部署支持 Rocky Linux 9.4 x86_64、Ubuntu 22.04/24.04 和 Debian 12。Rocky 使用 DNF 和 Docker 官方 RHEL 软件源；检测到冲突的 Podman、runc 等运行时包时会停止并提示，不自动卸载。保留 SELinux 和 firewalld 策略：软件管理的配置目录使用容器共享标签，业务绑定目录的标签由管理员准备，监控服务器需要能够访问目标主机的 TCP 9100。

支持本地目录、HTTPS Git 分支和提交 SHA。私有仓库填写访问令牌，令牌不放进 URL。源码在本机生成独立快照后上传；不会在 Windows 执行项目安装或构建脚本。

上传排除 `.git`、`node_modules`、Python 虚拟环境、`.env*`、常见私钥及符号链接。单文件最大 20 MB，总量最大 200 MB，最多 10,000 个文件。需要的运行时配置请填入环境变量，不依赖被排除的 `.env`。

| 模板            | 示例目录          | 安装命令                                       | 构建/启动                     | 容器端口 |
| --------------- | ----------------- | ---------------------------------------------- | ----------------------------- | -------- |
| 前端静态站点    | examples/frontend | npm install                                    | 构建 npm run build，输出 dist | 80       |
| Node.js 服务    | examples/node     | npm install                                    | 启动 npm start                | 3000     |
| Python Web 服务 | examples/python   | pip install --no-cache-dir -r requirements.txt | 启动 python app.py            | 8000     |

无 package-lock.json 的项目不要使用 `npm ci`；识别按钮会按锁文件情况选择命令。应用必须监听 `0.0.0.0`，健康检查路径应在容器启动后返回成功响应。前端构建时的环境变量应在项目构建配置中管理；向导中的环境变量供运行期使用。

每个方案使用独立 Docker 网络、Compose 项目和 Caddy。IP 模式可为不同应用分配不同 HTTP 端口；域名 HTTPS 模式占用 80/443，因此首版一台主机只能有一个占用这些端口的部署方案。DNS 需指向可达服务器，80/443 需按网络环境开放；软件不修改防火墙。

持久化映射使用服务器上已经存在的绝对目录。带持久化映射的应用更新时会先停止旧版，避免两个版本同时写入同一目录，因此会有短暂停机。候选版本失败时尝试恢复旧版。应用版本保留最近三个成功版本，回退不回退数据库或持久化文件。点击「同步版本」可在应用重启后重新读取远端发布记录。

远端管理目录：`/opt/sre-workbench/deployments/<方案ID>`。仅清理该方案淘汰版本的容器、镜像和源码目录，不执行 Docker 全局 prune，也不删除绑定的业务数据目录。

## 监控告警

监控服务器安装 Prometheus、Grafana、Alertmanager；每台选定主机安装 Node Exporter。采集地址必须为监控服务器可达的内网/VPN IPv4 地址，端口 9100。首次部署前请核实这条网络路径。不同监控实例必须使用不重叠的管理端口，并消耗额外内存和磁盘；只想更新已有实例时应编辑原方案。

Grafana 初始用户名默认 `admin`，可填写其他用户名；初始密码为你填写的值。账号仅在首次创建数据卷时初始化。再次部署保留数据卷，修改向导中的用户名或密码不会覆盖 Grafana 数据库中的既有账号，请使用原账号登录并在 Grafana 中管理。工作台不自动重置旧实例密码。

在「高级设置：监控访问端口」中可设置 Grafana、Prometheus、Alertmanager 的服务器映射端口，默认分别为 3000、9090、9093，范围 1–65535，三者不能重复。容器内部端口保持默认，服务器映射仅绑定远端回环地址；「打开 Grafana」通过本机随机端口 SSH 隧道访问。软件关闭后隧道关闭，但 Linux 上的采集、规则计算及邮件/Webhook 通知继续运行。

确认部署时会先检查端口冲突，实际准备部署时再检查；另一工作台实例占用时会显示方案 ID。打开页面、查询状态或操作告警前核实端口与方案归属，部署失败的方案不会再打开旧实例。如果端口已修改但尚未重新部署，访问会被阻止。保存方案关闭其已有隧道，部署完成后重新打开页面。

邮件通知默认关闭。启用后选择 QQ、163、126 或自定义 SMTP。「SMTP 发送账号」用于发送告警，预设服务同时用它登录 SMTP；「告警接收邮箱」是实际收件地址，两者可以相同，多个收件人用英文逗号分隔。「SMTP 授权码」对 QQ / 163 等邮箱指客户端授权码，不是网页登录密码；先在邮箱中开启 SMTP 服务并生成授权码。已有授权码留空保留，只有明确填写新值才替换，不回显真实值。

自定义 SMTP 的设置默认展开，可明确填写主机:端口及认证用户名；发送地址和认证用户名可以不同，用户名留空表示免认证中继。465 使用直接 TLS，其他端口要求 STARTTLS；界面显示这项固定策略，始终验证服务器证书。编辑已有预设方案时，服务器和认证账号仍匹配预设才显示对应服务商；特殊认证配置按自定义保留。修改或关闭通知后，需要重新部署监控方案才会影响远端通知。

告警分组时间及 Webhook 位于高级设置。Webhook 必须接收 Alertmanager 标准消息，并非企业微信群等专用机器人协议。测试通知通过 Alertmanager → notifications 接收器 → 邮件/Webhook 发送；提交后会读取测试告警状态，提示静默或抑制，后续读取失败时提示状态待确认且不会自动重发。提交成功不证明 SMTP 接受或邮箱收件；首次通知按 groupWait 等待，请检查收件箱与垃圾邮件，必要时查看 Alertmanager 的 SMTP / receiver 错误。静默使用精确告警名称，例如 `HighCPU`，并填写原因和时长，不自动撤销既有静默。

更新时备份原配置至 `/opt/sre-workbench/monitoring/<ID>/backups`，保留数据卷，重建容器加载配置。配置验证或健康检查失败会显示失败任务；必要时由管理员使用备份恢复。软件不会自动删除历史监控数据。

本地监控增量修复强化了验收：Compose 返回 0 后，仍须取得 Grafana `database=ok`、Prometheus ready、Alertmanager ready 及所有目标的 Node Exporter 主机指标。任务日志逐项显示 `SRE_MONITOR_CHECK`，任一失败会以非零退出，不能算部署成功。打开管理界面先核实实例归属与健康，再探测真实 SSH 转发，转发失败不会只返回一个可监听的本地地址。缺失本地状态不会自动接管未知端口；这些增量尚未发布到 v0.4.0 安装包，验证记录见 [监控专项验收](testing/2026-10-03-monitoring.md)。

## 任务中心

脚本、应用和监控部署提交后自动打开执行反馈，显示关联任务状态、日志、步骤和退出码；关闭面板后仍可在任务中心查看。

同一主机的变更串行，最多三个主机任务并发。远端长任务使用 systemd 单元，日志与退出记录位于 SSH 用户目录下的 `.local/share/sre-workbench/jobs/<任务ID>`。源码传输等准备工作需要桌面软件保持运行；远端作业提交后可独立运行。

断线、应用退出或主机重启导致状态无法确认时，显示「状态待核实」。点击「核实状态」重新连接读取结果；不会自动重复运行未知任务。取消只停止对应进程，不能撤销已经发生的变更。远端日志最多保留约 1 MB，超过上限会标注并以非零状态结束，避免无限输出写满磁盘。

## AI 与本地数据

模型接口支持自动识别、OpenAI 兼容和 Anthropic 兼容协议。DeepSeek Anthropic 地址填写 `https://api.deepseek.com/anthropic`，选择自动识别或 Anthropic，模型名称使用你的服务实际支持的模型 ID，保存后点击「测试连接」。它发送固定短句，不发送主机日志，可能消耗少量 API 用量。OpenAI 兼容接口按服务说明填写基础地址；也接受完整 `/chat/completions` 或 `/messages` 地址。Agent 填完整接口 URL。远端 API 使用 HTTPS，本机回环地址可用 HTTP。API 请求支持取消和超时，不自动重试。

### AI 任务助手

在「AI 助手 → 任务助手」左侧上方选择模型、已检测并信任的服务器及执行权限；左侧下方为对话历史，右侧输入指令并查看 AI 执行输出。仅提供服务器目标，不再提供 Windows 本机选项。一次会话固定服务器和权限；更换时点「新对话」。旧记录保留，标题旁可重命名。外部 HTTP Agent v1 使用「脚本助手（兼容接口）」。

| 权限             | 行为                                                                     |
| ---------------- | ------------------------------------------------------------------------ |
| 分析建议         | 仅分析需求，不调用工具                                                   |
| 只读诊断（默认） | 读取工作目录中的文件、固定系统信息、HTTP 回环地址；不执行任意 Shell      |
| 确认执行         | 读取自动进行；每次写文件、建目录及终端命令需确认具体内容，确认十分钟过期 |
| 自主执行         | 提交即授权在本次任务中连续调用工具；自动执行、读取结果、修正及验证       |

「工作目录与高级设置」可填写服务器绝对路径，写权限下可由 AI 创建新目录；需要提权时勾选已配置的 sudo。结构化文件工具会核对目录边界和符号链接；**终端不是操作系统沙箱**，工作目录仅为启动位置，命令可访问该系统账号有权访问的资源，不能理解为所有命令副作用都被目录隔离。

例：选择测试 Linux 主机、独立目录 `/opt/my-blog` 和自主执行，输入「使用 Nginx、Flask、Python 创建个人博客，页面精简。生成完整项目和依赖说明，使用空闲端口部署，验证首页并告诉我访问地址。保留服务器上已有服务。」AI 会按实际环境调用工具；缺少必要条件时提问。此类博客部署已在 Rocky Linux 9.4 完成实测。

任务会显示每一步的工具参数、输出及关联远端任务；支持确认、拒绝、停止以及补充指令继续。模型结束回复中的验证引用只有对应已成功工具步骤才显示，引用仍需结合输出判断，不能代替你的验收。没有成功验证引用时会明确提示未验证。每轮默认最多 40 步，可选 1–100 步；每个会话最多 200 条记录，单条命令最长 30 分钟，模型请求沿用设置中的超时。

提交任务时，需求及工具读取的相关文件/输出会在脱敏后发送给所选模型，步骤保存在本机。不要选择与任务无关的敏感目录。工具参数如包含需脱敏的信息会被拒绝，模型应使用环境变量等方式，避免把密码直接写入命令或代码。未知业务秘密仍需要自行检查。

「暂停」等待当前操作结束，暂停后续步骤并保留上下文；「继续」从已有结果接着处理，不重放已完成命令。暂停待审批操作会使旧审批失效，继续后需重新审批。「停止」取消模型请求并尝试终止当前远端任务；已完成变更不会回滚。短只读 SSH 检查可能需等待超时返回。

AI 执行记录不再显示在任务中心，在当前会话展开步骤即可查看远端日志、核实或终止操作。旧 AI 关联记录也会自动归类，不删除执行数据。断线或重启的不确定执行不会自动重放，应在会话内核实实际状态，再点击「我已核实实际状态」。同一时刻只运行一个 AI 会话；远端变更仍使用主机任务队列。

自定义 Agent、工作流编排和 Tool／Skill 导入在 Agent Studio 中管理，详见下文。当前不含浏览器／桌面点击控制；服务器运行项目所需的 Python、Nginx、Docker 等取决于目标环境。

### 兼容脚本助手

模型的 JSON 脚本草稿可编辑、保存版本并选择目标主机。执行确认绑定完整脚本、主机和 sudo/超时设置；任何改动都需重新预览。该兼容入口不会根据 AI 返回内容自动运行命令。

本地数据目录通常为 `%APPDATA%/sre-workbench`。退出软件后可备份整个目录；凭据绑定当前 Windows 加密上下文，复制数据库到另一台电脑不代表密钥可解密。卸载默认保留个人数据。不要把数据库或远端包含秘密的配置备份发布到公开仓库。

## 删除记录

应用和监控方案可删除本地配置，关联的本地凭据及应用版本记录一并移除；远端容器、数据及监控通知继续运行，不会被卸载。删除方案后无法再通过原方案管理远端部署，请先确认是否需要保留管理入口。脚本库按版本删除，任务历史保留。已结束任务可删除本地记录和日志；排队、运行、待核实、正在收尾或仍被后续监控任务依赖的记录不可删除。

## 内置 SRE 诊断技能

AI 助手新任务配置中的“SRE 技能”可选择自动匹配、通用任务、Linux 环境巡检、监控无数据排查。任务开始时保存所选技能版本与指令；未完成任务继续时保持技能，已完成后补充新需求且使用自动匹配时重新选择技能并保留版本历史，手选技能保持不变。旧会话保持兼容。

建议以“只读诊断”测试：

- Linux 环境巡检：`检查这台服务器的系统资源、磁盘容量、inode、监听端口和时间同步，列出异常证据，不修改系统。`
- 监控无数据排查：`检查这台服务器上平台部署的 Grafana 为什么没有数据，先检查时钟，再检查 Prometheus targets 和指标，列出证据与未验证项，不修改配置。`
- 日志诊断：`查看 nginx.service 最近 30 分钟的日志和当前状态，分析异常，不重启服务。`

新增工具：host_resources、clock_status、network_listeners、service_status、service_logs、container_logs、monitoring_query。执行权限继续由平台后端校验；分析建议模式不能调用工具，只读模式不能运行任意终端命令。

服务/容器日志最多 300 行、时间范围最多 24 小时；工具结果包含采集时间、目标、退出码和截断标识，会话展示证据编号。输出会脱敏。采集成功不代表服务健康，模型结论仍应结合原始输出审阅。

monitoring_query 只允许查询该目标服务器在平台中保存的监控方案，复用已配置端口，支持 Prometheus targets/即时查询/范围查询和 Grafana health；不直接访问任意地址、不提供 Grafana 登录凭据。范围查询按客户端时间计算，时钟偏差需先排查。Grafana health 不证明数据源、登录或面板配置正确，这些仍可能需要补充检查。

容器查询固定 `/var/run/docker.sock`，避免账号 Docker context 意外指向其他主机；自定义 socket 和 rootless Docker 尚不支持。Linux 工具依赖目标系统提供 systemd/journalctl、ss、Docker 或 curl 等对应命令，缺少依赖或权限时报告失败，不自动安装。

## 自主部署与修复

选择服务器、工作目录、模型、“自主执行”，技能使用自动匹配或“应用搭建与部署”“故障定位与修复”。提交明确需求后，Agent 可在授权范围内连续预检、规划、创建文件、运行命令、部署及核验，不逐项确认。确认执行模式仍需逐项审批变更。缺少必需输入、状态不明、连续失败或步骤预算耗尽时会暂停或请求补充。

示例：`在 /opt/my-blog 创建一个 Nginx + Flask + Python 个人博客，简洁风格，使用空闲端口，保留已有业务，完成后验证页面并提供访问地址和维护说明。`

新增工具 update_plan、service_action（start/restart/reload）、compose_check、compose_action（up/restart）、verify_service（服务 active、HTTP 2xx、可选正文文字），以及下文分类验收的verify_file、verify_package。当前共21项工具与4项内置技能。Compose依赖可用的Docker Compose v2和--wait支持，固定本机默认socket，不支持rootless/custom socket。

新SSH会话变更前必须有计划和成功前置观测。计划可在聊天区展开查看，包含进度与验收标准；进度是模型根据步骤证据维护，不代表平台独立证明全部业务正确。变更后必须提供新的独立验证，不能把变更前观测或执行命令当成验收。没有声明分类checks的旧流程保留原规则：部署/修复、任意shell或服务/Compose动作要求服务/HTTP验证，纯文件工具任务允许read_file/compose_check复核。新任务可在变更前声明下文分类checks，让文件/安装包任务使用对应结果验收。未提供合格验证的完成请求会被拦截，不能声称所有运维任务已全面自动化。

SSH write_file 写入已有文件时保存同目录随机后缀备份，写入临时文件、复核原文件摘要，再原子替换；日志输出 SRE_BACKUP 路径。保存原权限/属主和启用 SELinux 时的上下文。保护仅覆盖此文件工具，不覆盖 run_command 自行写入、数据库迁移或数据删除。并发锁是协作锁，不能阻止外部程序同时写入；中断遗留锁需核实，不能盲目清理。回滚仍需 Agent 根据备份及实际影响执行，不是通用自动事务回滚。

暂停保留计划和结果；未完成会话补充“继续”不会清除待验收状态。已完成任务补充新需求才开启新的验收区间；状态不明不自动重放。达到步骤上限需要用户检查后继续。

2026-09-21 已通过 Rocky Linux 9.4 + 真实 DeepSeek 的 Python/systemd 博客部署、首页更新备份、停机恢复、HTTP公开文件边界修复及浏览器检查。首次部署中发现流程提示不足，修改后从原会话继续完成，不能据此承诺任何需求均可一次自动成功。本轮未覆盖Docker/Compose、数据库迁移、断网恢复及并发任务；详见 testing/2026-09-21-agent-autonomous-live.md。已发布 v0.2.2 安装包不含这些增强。

run_command即使执行只读检查，也统一按可能变更处理。先完成所有命令，再执行对应的独立验收工具并引用新步骤ID；最终查看状态/端口优先用service_status/network_listeners，避免使刚取得的验收失效。首次观测使用host_resources/network_listeners/inspect_system，不依赖工作目录已经存在。

部署技能1.0.1要求公开页面与源码、配置、凭据、日志、备份隔离，并检查非公开文件请求返回403/404。write_file 的同目录备份仍在原目录；不能把整个项目目录作为静态网站公开。技能是给模型的执行指导，平台不能据此保证任意生成应用的安全性，交付仍须实际验证。

2026-09-22 补充：service_status 可直接返回 UnitFileState、FragmentPath/DropInPaths、WorkingDirectory、User/Group、Restart/NRestarts、ExecMainCode 等信息，只读权限下无需运行shell即可区分“正在运行”和“开机自启”。network_listeners 返回账号可见的进程名/PID，普通账号可能看不到其他用户进程，缺失不等于端口无人使用。工具不读取服务 Environment 或完整 ExecStart。

巡检及故障修复技能1.0.1要求结合退出状态、日志、实际加载配置与端口归属定位原因，修正配置前备份并校验；不能为了释放端口停止无关业务。systemd-analyze 校验副本需保留.service等合法后缀。修复后复核服务状态与业务，满足验收后直接交付。真实模型仍可能请求不必要的补充，收尾提示已加强，但不保证每次均一次成功。新增错误启动路径和端口冲突实测见 testing/2026-09-22-agent-sre-debugging.md。

## 文件与安装包分类验收

可以直接提出：“在独立目录运行Python批处理生成summary.json，包含系统名、生成时间和ready状态；不要创建HTTP服务。”Agent应在首次变更前将文件、安装包断言写入计划checks，最后逐项执行并引用结果。

- 文件验收verify_file：路径在任务根目录内，普通文件最大1MiB，默认至少1字节；支持format=binary/text/json/python、expectText正文包含、sha256摘要和mode权限。JSON/Python只做语法解析，不执行脚本；JSON拒绝NaN/Infinity。文件工具依赖/usr/bin/python3。minBytes=0仍要求文件存在，不表示“文件不存在”。需要断言不存在时使用verify_file {path,exists:false}，此分支不能同时填写格式、正文、摘要或权限；悬空符号链接也视为存在。计划保存前会检查文件验收路径位于本任务目录内；纯数字短计数断言不会因同值短密码被误拦截。verify_file已升级1.1.1、update_plan为1.1.0，旧会话固定版本不会自动替换，升级后需要新建任务先核实已有结果。模型每轮获得真实证据索引和后台核定的待验收项，仍须提交有效证据，不能跳过权限/验收。
- 安装包验收verify_package：RPM/DEB系统包是否已安装，可选精确version。RPM版本不含发行修订RELEASE，DEB采用完整Version；不覆盖pip/npm及源码安装。
- checks最多8项，首次变更后锁定。后续更新计划须原样保留；每项必须有最后变更之后的成功匹配证据。需要改变目标或验收范围时应停止并新建明确任务。
- 网站、服务和Compose操作仍需服务/HTTP验收，不能以文件存在替代。旧会话未声明checks时沿用原规则，不会自动降级。

计划面板会显示这些实际条件。语法正确、正文包含某词或包已安装只证明对应断言，不保证业务语义、完整依赖或备份可恢复；必要时应增加针对性测试。本轮真实批处理+文件/包验收已通过，DEB尚未实机测试。

## AI断线恢复与长任务

远端命令由持久systemd作业承载。暂时断线时只重查状态，不自动重提命令；连续查询失败最多5次，之后显示待核实。在会话步骤中可查看阶段日志、起止时间、最近核实时间及失败次数，并点击“核实远端状态”重查。

软件意外退出后，原AI会话进入待核实。点击“核实并恢复会话”，系统校验目标与关联作业；结果明确后同步退出码/日志并恢复为暂停，点击“继续”处理剩余计划与业务验收。仍在运行或结果不确定时继续拦截。没有可靠作业记录的中断变更需要人工核实，不能用继续按钮跳过。

计划、步骤和远端作业构成检查点；并不支持任意脚本内部逐行续跑。安装、迁移、部署宜拆为可独立核验的阶段。自动重试只针对状态查询，变更失败后须先判断已完成范围，再由Agent诊断修复。配置身份改变、远端元数据丢失等情况不自动恢复。

Compose工具的path必须是配置文件（如compose.yaml），不是目录。修改后先校验Compose及应用自身配置，再应用并验证容器健康和HTTP；文件检查通过不能替代业务验收。

恢复和 Compose 实测范围、失败记录及限制见 [验收报告](testing/2026-09-27-agent-recovery-compose.md)，Studio 新实验见 [Benchmark 报告](testing/competition-agent-benchmark.md)。v0.4.0 包含这些能力；恢复实测不代表覆盖 Windows 重启或任意脚本逐行续跑。
