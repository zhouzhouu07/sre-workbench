# Agent 断线恢复、长任务与 Compose 实测

日期：2026-09-27。修改仅在本地源码和构建目录，未打包、提交、推送或发布。凭据不记录。测试使用隔离数据库，测试会话不会出现在用户日常应用历史中。

## 实现范围

- 远端作业运行中或未知时继续查询持久退出码、systemd 状态与日志。连续未知/查询失败最多5次，退避约2/4/8/16秒；到上限停止自动查询，可手动核实。
- 重试的是状态查询，不重新发送变更命令。短暂查询中断时 AI 工具等待自动核实；耗尽重试后保留未知状态，阻止后续变更。
- 查询合并，避免同一作业并发核实；新作业绑定主机连接身份，配置变化后拒绝向新目标查询或发送停止命令。旧作业缺少身份元数据，不能追溯补充同等保证。
- 新增 `ai.session.reconcile`：检查关联作业归属，同步终态、退出码和日志。结果确定后恢复为暂停，用户点击继续，模型基于现有记录继续验收。仍运行、元数据丢失、无作业标识的中断变更保持未知，不自动放行。
- 界面新增“核实并恢复会话”，保留人工核实后结束；展示步骤起止时间、远端阶段/日志、最近核实时间和连续失败次数。计划和证据仍持久保存，不展示虚构完成百分比。
- 文件父目录缺失与 Compose 参数误填目录时返回准确提示。计划验收失败反馈列出锁定 checks 的完整参数，防止反复执行错误路径的验收。
- 部署/修复技能升级1.0.2，补充阶段检查点、目录准备、Compose 文件参数、配置与应用语法校验、最小修复和依据工具证据报告结果。

## 回归与使用边界

- 类型检查、全量单元测试、生产构建结果见根目录项目进程最终记录；Electron8项通过，包含恢复按钮、日志检查点和继续入口。Browser插件未提供，采用项目现有Electron/Playwright；界面截图经过检查，无页面运行异常。
- 检查点是已执行步骤、远端作业ID、计划和结果；不会把任意长脚本内部任意行变成可续跑事务。大任务应拆成有独立验证的阶段。
- 不确定状态不能通过点击继续跳过；永久丢失远端状态、VM重装或无作业标识的变更仍需人工核实。模型API网络故障没有新增通用自动重试策略。
- 失败后的下一项操作仍由模型结合证据决定，既有连续失败上限仍生效。没有实现通用幂等事务、数据库迁移回滚或跨主机编排。
- 测试保留两个本轮Compose项目、恢复计数目录和备份。访问18090需SSH隧道，例如本机 `ssh -L 18090:127.0.0.1:18090 root@10.3.128.3` 后打开 `http://127.0.0.1:18090/`。
