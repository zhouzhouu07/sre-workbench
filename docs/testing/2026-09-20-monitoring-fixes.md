# 监控模块修复验收

本轮基于 v0.1.2 后续源码；这些修复已纳入 v0.2.0 安装包，并验证打包程序中的用户名和端口界面。具体发布状态见根目录 `项目进程.md`。

## 修复范围

- 可填写 Grafana 初始用户名，默认 admin；明确已有数据卷账号不会被重新部署覆盖。
- 可配置 Grafana、Prometheus、Alertmanager 回环映射端口，校验范围和重复值；兼容旧方案默认值。
- 状态、测试告警、静默、健康检查和 SSH 隧道使用配置端口。
- 服务访问前核对 Compose 项目、服务名和回环映射，拒绝未部署或指向其他实例的方案。
- 部署开始前识别其他 Docker 实例的端口占用，包含端口范围，明确另一工作台方案的 ID；实际准备阶段再次检查。
- 保存配置关闭该方案旧隧道。不同实例使用不同端口；不自动接管、重置或删除旧实例。

## 实机验证

Rocky Linux 9.4，保留原监控和业务应用。新增隔离测试方案，用户名 operator，端口 13000/19090/19093。

- 部署任务退出码 0，实际 Grafana POST /login 返回 200（非仅验证健康页）。
- 自定义端口状态查询 success，测试告警与静默 API 成功。
- 三个服务通过工作台创建的 SSH 隧道访问均返回 HTTP 200。
- 同方案重复部署后，原 operator 账号仍可登录，全部自定义端口操作再次通过。

本地验证：96 项单元测试、4 项 Electron 界面回归通过；类型检查和构建通过。界面测试包含用户名输入、重复端口阻止保存和修正端口后保存。测试结束停止本轮隔离实例，保留数据卷，原监控和用户示例应用不作变更。

测试凭据不纳入报告或仓库。真实邮件投递和浏览器覆盖升级不属于本轮通过项。
