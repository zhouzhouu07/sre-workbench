## 1. 软件是什么

**SRE Workbench（SRE 运维工作台）** 是一个 Windows 中文桌面运维软件，通过 SSH 连接 Linux 服务器，将主机查看、文件管理、终端、应用发布、监控告警、脚本执行和 AI 运维任务集中在同一个工作空间中。

**SRE Agent Studio** 是工作台内的 Agent 配置与执行管理模块，用于管理工具和技能、构建专用助手、编排工作流、查看风险与执行证据，以及开展真实运维对照实验。它与基础运维页面共用主机、模型配置和远端任务机制。

软件适合个人运维、开发者、小型项目维护，以及 SRE 自动化实践和竞赛演示。典型用途包括：

- 查看 Linux 的资源、进程、服务、容器和日志。
- 上传、下载、编辑服务器文件，打开 SSH 终端。
- 将前端、Node.js、Python 或自带 Dockerfile 的项目部署为服务。
- 部署 Prometheus、Grafana、Alertmanager 和 Node Exporter。
- 保存脚本版本，审阅后执行并查看远端结果。
- 让 AI 在指定权限下诊断、部署、修复并提交实际工具证据。
- 将重复操作整理为版本化 Agent 或 Workflow。

普通主机管理、脚本、部署和监控操作不依赖模型 API。AI 助手、Workflow 中的 Agent 节点，以及含模型调用的 Benchmark 才需要可用的模型服务和额度。

## 2. 功能导航与核心概念

### 2.1 主界面导航

| 入口 | 主要作用 | 适合处理的事情 |
| --- | --- | --- |
| 总览 | 查看配置数量、进行中任务及最近执行 | 进入软件后快速定位工作 |
| 主机管理 | SSH 配置、检测、主机详情、终端、SFTP | 查看和操作单台 Linux 主机 |
| 应用部署 | 保存发布方案、预检、部署、版本回退 | 重复发布已有应用源码 |
| 监控告警 | 部署监控组件、采集目标与通知规则 | 持续监控服务器资源 |
| 任务中心 | 查看普通运维任务的状态、日志、退出码 | 跟踪执行、取消、核实未知结果 |
| 脚本库 | 编辑、保存和执行脚本版本 | 复用人工编写或审阅过的操作 |
| AI 助手 | 任务助手及兼容脚本助手 | 自然语言诊断、生成脚本、执行授权任务 |
| Agent Studio | Tools、Skills、Agents、Workflows、Runs、Benchmark | 配置、编排、追溯和评估自动化 |
| 设置 | 模型 API 与外部 HTTP Agent 配置 | 保存接口、模型、认证与超时 |

顶部支持刷新数据和切换明暗主题，主题选择在本机保留。

### 2.2 几个容易混淆的概念

| 名称 | 在软件中的含义 |
| --- | --- |
| 主机 | 已保存的 Linux SSH 连接配置，连接前要核实服务器指纹 |
| Task | 实际远端执行作业，记录日志、退出码和恢复信息 |
| Tool | 平台提供的具体操作能力，例如读取文件、查询服务、执行命令 |
| Skill | 给模型的操作方法、工具依赖、限制与验收建议，本身不提升权限 |
| Agent | 模型与工具、技能、权限、目标范围、预算等配置的组合 |
| Workflow | 由节点和连接组成的执行流程，可以调用 Tool 或 Agent |
| Risk | 后端对调用的风险评估及允许、审批、拒绝策略 |
| Trace / Runs | 已保存的执行过程、版本和工具证据 |
| Benchmark | 使用隔离资源与独立验收的对照实验 |

例如，修复一个服务时，Agent 可以按照 Skill 的方法提出 Tool 调用；后端检查权限和 Risk，必要时等待审批；长命令由 Task 承载；执行过程最后汇入 Trace。模型的描述不替代实际日志与验收结果。

## 3. 安装与首次配置

### 3.1 Windows 端

正式安装包为 `SRE.Workbench.Setup.0.4.0.exe`，可从 [v0.4.0 发行页](https://github.com/zhouzhouu07/sre-workbench/releases/tag/v0.4.0) 获取。普通使用无需在 Windows 安装 Node.js、Python、Git 或 Docker，软件包含所需桌面运行环境和 Git 工具。

### 3.2 Linux 端要求

- 服务器可通过 SSH 访问，账号具有任务所需权限。
- 长任务依赖 systemd，目标主机需要以 systemd 作为 PID 1。
- 非 root 账号运行不使用 sudo 的持久作业时，需要预先启用该用户的 systemd lingering，并保证 `systemctl --user` 可用。
- 部署任务需要服务器能够访问相关软件源、镜像仓库和构建依赖。
- 软件提供 Rocky Linux 9.4、Ubuntu 22.04/24.04、Debian 12 x86_64 部署路径，主要真实验证环境是 Rocky Linux 9.4；其他发行版仍需单独验收。

### 3.3 推荐的首次使用顺序

1. 在「主机管理」添加服务器地址、SSH 端口、账号和认证方式。
2. 执行连接检测，核对并信任 SSH 指纹。
3. 打开「管理」，确认资源、服务、端口与现有业务。
4. 按需求创建应用部署或监控方案；可以先使用普通运维功能。
5. 需要 AI 时，在「设置」添加模型 API，填写服务实际支持的模型 ID。
6. 从「只读诊断」开始使用任务助手，检查实际输出后再选择变更权限。
7. 需要重复自动化时，再配置 Agent 和 Workflow。

## 4. 总览

总览展示已添加主机、部署方案、监控方案和进行中任务数量，提供主机、发布、监控、AI 与 Studio 的快捷入口，并展示最近任务。

这里的主机、应用和监控数字主要表示本地保存的配置数量，不代表所有服务器在线或所有服务健康。任务状态异常时，应进入对应记录查看日志和核实结果。

**用法：** 进入软件后先看进行中和最近任务；需要继续某项工作时，通过快捷入口进入对应模块。远端资源的实时情况仍需在主机、监控或任务详情中读取。

## 5. 主机管理

### 5.1 添加、编辑与检测

可保存主机名称、地址、SSH 端口、用户、分组和标签，认证支持密码或私钥；带口令的私钥可单独填写口令，需要提权时可配置 sudo 密码。

**用法：** 点击「添加主机」填写信息，保存后检测连接。首次连接核对指纹，确认属于目标服务器后信任。编辑凭据时留空表示保留原凭据。

指纹变化时连接会被拒绝。核实服务器重装或密钥变更后，需要删除并重新添加配置，不能把变化直接当作普通连接错误忽略。删除主机配置不删除 Linux 上的文件或服务。

### 5.2 主机详情

点击主机的「管理」，可以切换以下页面：

| 页面 | 功能 | 使用方式 |
| --- | --- | --- |
| 系统概览 | 查看系统与资源信息 | 打开后读取，必要时刷新 |
| 进程 | 查看进程信息 | 用于观察资源占用与正在运行的程序 |
| 系统服务 | 查看 systemd 服务，操作指定服务 | 填写服务名，如 `nginx.service`，查看或预览启动、停止、重启 |
| 系统日志 | 查看系统或指定服务日志 | 填写服务名并刷新读取 |
| 容器 | 查看 Docker 容器与指定容器日志 | 填写容器 ID/名称，读取日志或预览启动、停止、重启 |
| 文件管理 | SFTP 目录浏览、文件读写和传输 | 输入远端路径后打开目录 |

服务和容器的变更操作需要审阅实际目标及执行内容，再确认执行。资源或日志读取失败可能是权限不足、命令缺失或连接问题，不表示系统正常。

### 5.3 SSH 终端

主机页面可打开交互式 SSH 终端，并通过多标签切换不同终端会话。适合手工排查、执行明确命令和查看实时反馈。

终端命令使用当前 SSH 账号的实际系统权限。它不受 AI「只读诊断」模式保护，也不构成文件系统沙箱；执行前应自行确认命令及影响范围。

### 5.4 SFTP 文件管理

支持目录浏览、读取与编辑文本文件、上传、下载、新建目录、重命名/移动，以及删除文件或空目录。

**用法：** 打开远端目录，点击文件名查看文本；保存时确认覆盖。上传选择本地文件，核对远端目标路径；下载选择本地保存位置。重命名可填写新的完整远端路径。

上传同名文件会覆盖，删除不提供通用恢复。主机页面的文件管理按 SSH 账号权限操作，不应将它与 AI 任务目录内的结构化文件工具边界混为一谈。

## 6. 应用部署

### 6.1 功能介绍

应用部署通过保存的方案完成源码快照、传输、远端镜像构建、健康检查和访问入口切换。适合发布已有项目，不需要依赖模型生成部署步骤。

| 模板 | 典型项目 | 主要配置 |
| --- | --- | --- |
| 前端静态站点 | 前端构建后的静态页面 | 依赖安装命令、构建命令、产物目录 |
| Node.js 服务 | HTTP API 或后端应用 | 依赖安装、可选构建、启动命令、容器端口 |
| Python Web 服务 | Flask 等 Web 项目 | 依赖安装、启动命令、容器端口 |
| 项目自带 Dockerfile | 已编写镜像构建方案的项目 | 项目 Dockerfile 及端口、健康检查等发布配置 |

源码可来自本地目录或 HTTPS Git 仓库，支持分支和提交 SHA，私有仓库可填写访问令牌。

### 6.2 发布步骤

1. 新建部署方案，选择目标主机和源码来源。
2. 选择模板及运行时，检查识别出的安装、构建、启动命令。
3. 配置容器端口、HTTP 入口端口、健康检查路径和可选域名。
4. 按需填写运行期环境变量 JSON 和持久化目录映射。
5. 保存方案，点击「部署」，查看环境预检。
6. 解决系统、权限、磁盘、端口等阻塞项，确认变更后执行。
7. 查看任务反馈，成功后访问应用；更新时可使用同一方案再次发布。

确认后任务会按需安装 Docker，并启用 Docker 开机自启。实际安装、构建和项目脚本在 Linux 上执行；Windows 端不会运行项目的安装或构建脚本。

### 6.3 版本与回退

每个方案使用独立 Compose 项目、网络和 Caddy 入口。保留最近三个成功发布版本，支持选择版本回退；「同步版本」可重新读取远端发布记录。

回退切换应用发布版本，**不会回退数据库或持久化文件**。带持久化映射的更新会先停止旧版，避免两个版本同时写入同一目录，因此有短暂停机；候选版本失败时尝试恢复旧版。

### 6.4 使用注意

- 应用需要监听 `0.0.0.0`；健康路径应在容器启动后返回成功响应。
- 无锁文件的项目不要使用 `npm ci`，应检查向导识别出的命令。
- 运行期环境变量不自动等同于前端构建期变量。
- 上传排除 `.git`、依赖目录、虚拟环境、`.env*`、常见私钥和符号链接；单文件上限 20 MB，总量 200 MB，最多 10,000 个文件。
- 持久化映射的服务器源目录需要已存在；业务目录权限及 SELinux 标签由管理员准备。
- IP 模式可以为不同应用分配不同 HTTP 端口；域名 HTTPS 模式使用 80/443，当前同一主机只能有一个占用这组端口的部署方案。
- DNS、端口可达和证书签发需要目标环境满足条件，软件不自动修改防火墙。
- 删除本地部署方案不卸载远端应用；淘汰版本清理仅针对该方案，不执行 Docker 全局 prune 或删除业务数据目录。

## 7. 监控告警

### 7.1 组件与作用

| 组件 | 作用 |
| --- | --- |
| Node Exporter | 在采集目标主机上提供资源指标 |
| Prometheus | 抓取指标、保存时序数据、计算告警规则 |
| Grafana | 查看监控面板 |
| Alertmanager | 对告警分组、抑制/静默并发送通知 |

这些组件运行在 Linux 上。关闭 Windows 工作台后，服务器上的采集、规则计算与通知仍可继续。

### 7.2 部署与查看

1. 新建监控方案，选择监控服务器。
2. 添加采集主机及监控服务器可达的内网/VPN IPv4 地址。
3. 配置指标保留时间、Grafana 初始账号和密码。
4. 设置 CPU、内存、磁盘阈值与触发持续时间。
5. 按需设置邮件、Webhook、告警分组及管理端口。
6. 保存并部署，审阅变更和端口预检，查看任务结果。
7. 打开 Grafana 或查看采集目标与告警状态。

监控服务器需要能访问采集主机的 TCP 9100。管理服务的远端映射端口绑定回环地址，通过工作台建立的 SSH 隧道访问；默认 Grafana、Prometheus、Alertmanager 端口为 3000、9090、9093，可以在高级设置修改，不能相互重复。

### 7.3 通知与静默

邮件支持 QQ、163、126 和自定义 SMTP，可设置发件邮箱、授权码与收件邮箱。465 使用直接 TLS，其他端口要求 STARTTLS，不跳过证书验证。Webhook 使用 **Alertmanager 标准消息协议**，不直接等同于企业微信群等专用机器人接口。

可发送测试告警，也可对准确的告警名称设置静默、原因和时长。测试请求被接收不代表邮件已送达，应检查收件邮箱与 Alertmanager 日志；通知还会受分组等待时间影响。

### 7.4 更新与保留

配置修改后需要重新部署才能改变远端规则或通知。更新备份配置并保留数据卷，不自动删除历史监控数据。

Grafana 账号只在首次创建数据卷时初始化；再次部署不会用向导中的新密码覆盖旧账号。多个监控方案应使用不重叠的端口，操作前核实方案归属。删除方案仅移除本地管理配置，远端监控与通知仍可能继续。

## 8. 任务中心

任务中心用于查看脚本、部署、监控等普通运维任务。任务详情显示状态、步骤、日志和退出码，可核实状态、取消任务或删除允许清理的本地历史。

| 状态 | 含义 | 建议操作 |
| --- | --- | --- |
| 排队中 | 等待主机任务队列 | 等待或取消 |
| 运行中 | 已执行或正在收集执行结果 | 查看日志，避免重复提交 |
| 成功 | 收到成功终态 | 结合任务对应的健康检查确认业务 |
| 失败 | 得到失败结果 | 查看退出码与日志，判断已完成范围 |
| 已取消 | 已取消或终止任务 | 检查是否已产生部分变更 |
| 状态待核实 | 结果暂时无法确认 | 重新连接后核实原任务 |

同一主机的变更串行，最多三个主机任务并发。远端长任务由 systemd 承载；提交后的作业可以独立运行，但源码传输等提交前准备仍需要桌面软件保持运行。

**用法：** 打开任务详情查看当前步骤与日志；断线后先点击「核实状态」，不要重新执行同一未知任务。取消只停止对应进程，不撤销已有修改。远端日志有约 1 MB 上限，超限会标注并以非零状态结束。

AI 关联的 Task 在 AI 会话步骤中管理，不单独出现在任务中心列表；Agent/Workflow 的统一记录在 Studio → Runs 查看。运行、排队、待核实或仍被后续任务依赖的记录不能随意删除。

## 9. 脚本库

脚本库提供脚本编辑、按名称保存新版本、加载历史版本和选择主机执行。适合巡检、维护等需要人工审阅和重复使用的脚本。

**用法：** 输入脚本名称，在编辑器编写内容，点击「保存新版本」。执行时选择主机、sudo 和超时，预览完整执行内容后确认，随后查看任务反馈。

脚本执行确认绑定脚本内容、主机及执行设置；修改内容或设置后需要重新预览。删除某个版本只删除保存的脚本版本，不删除任务历史。脚本可产生实际服务器变更，保存成功不表示执行成功。

## 10. AI 助手

### 10.1 任务助手

任务助手接收自然语言需求，调用受控工具读取环境、维护计划、执行授权操作、诊断失败并核验结果。它面向 SSH Linux 服务器，界面不提供 Windows 本机任务目标。

**用法：** 在「任务助手」选择模型、已检测并信任的服务器、权限和工作目录，按需选择 Skill 与 sudo，再提交明确需求。会话固定目标和权限，更换服务器或权限时新建对话。历史对话保留并可重命名。

### 10.2 四档权限

| 权限 | 可以做什么 | 变更要求 |
| --- | --- | --- |
| 分析建议 | 根据需求与已有上下文给出建议，可维护本地计划 | 不调用主机工具 |
| 只读诊断（默认） | 文件读取、固定系统观测、回环 HTTP 与监控查询 | 不执行任意 Shell，不做主机变更 |
| 确认执行 | 在读取基础上请求写文件、建目录、命令和服务/Compose 操作 | 逐项审阅具体内容后确认 |
| 自主执行 | 在本次明确授权任务中连续操作、修正与验证 | 仍受风险、白名单、验收和导入工具审批限制 |

`run_command` 即使命令看起来是只读查询，也统一按潜在变更处理，因此只读模式不能调用。自主执行不是无限权限，CRITICAL 风险仍被拒绝，受控导入工具仍逐次审批。

### 10.3 计划、证据与验收

变更任务需要前置观测与计划。每步记录工具参数、输出、Evidence ID 和关联远端 Task；变更后需要新的独立验收，不能用变更前信息或命令执行完成代替业务验收。

- 服务与网站：使用服务状态、HTTP 状态及需要的正文检查。
- Compose：先检查配置，再应用，最后核实容器与业务；配置合法不等于应用正常。
- 文件：`verify_file` 可检查存在/不存在、大小、格式、正文包含、摘要与权限。JSON/Python 格式检查不执行脚本。
- 系统安装包：`verify_package` 检查 RPM/DEB 包是否安装及可选精确版本，不覆盖 pip/npm 或源码安装。

文件/安装包分类 checks 需要在首次变更前声明，最多 8 项，变更后锁定；每项要有最后变更后的匹配证据。JSON 语法正确不代表字段业务值正确，文本包含也不等于完整业务测试。

模型总结可能不准确，交付时应阅读实际工具证据和未验证项。旧会话固定原工具版本，升级后不会自动换成新执行器。

### 10.4 暂停、继续、停止与恢复

- **暂停：** 等待当前操作结束，在步骤边界暂停并保留上下文；旧待审批会失效。
- **继续：** 依据已保存结果继续，已完成命令不重放；需要时重新审批。
- **补充输入：** 缺少必需信息时回答问题，明确后再继续。
- **停止：** 取消模型请求并尝试终止当前作业，不回滚已有变更。
- **核实远端状态：** 查询原作业，确认日志与退出码，不重新提交命令。
- **核实并恢复会话：** 中断后校验目标和关联作业，结果明确后恢复为暂停，再继续剩余任务。

结果仍未知或没有可靠作业记录时，需要人工核实，不能通过「继续」绕过。默认每轮最多 40 步，可选 1–100 步；普通会话最多 200 条记录，单条 Agent 命令最长 30 分钟。Agent Builder 的运行预算另有整体约束。

### 10.5 兼容脚本助手

「脚本助手（兼容接口）」用于让模型或外部 HTTP Agent 返回建议及 JSON 脚本草稿，保留原接口使用方式。

**用法：** 选择接口，填写需求与上下文；可以读取主机概览，预览脱敏后的发送内容再提交。收到脚本后人工编辑、保存版本、选择主机并确认执行。

它不会因为模型返回脚本就自动运行。外部 HTTP Agent 使用本软件的协议，不能直接作为 Agent Builder 的模型 API。

### 10.6 示例需求

只读诊断示例：

> 检查这台服务器的 CPU、内存、磁盘容量、inode、监听端口和时间同步，列出异常证据及未检查项，不修改系统。

故障诊断示例：

> 查看 nginx.service 的当前状态及最近 30 分钟日志，分析异常原因，不重启服务。

授权部署示例：

> 在独立目录创建一个 Flask Web 应用，使用空闲端口，保留已有业务。先预检和保存计划，部署后验证首页，提供访问地址、目录及维护方式。

最后一类需求会产生服务器变更，需要选择符合目标的执行权限。不要将密码、API Key、SSH 私钥写进需求或 Agent 定义。

## 11. Agent Studio

Studio 有六个页面入口，覆盖七个核心模块：Tool Registry / Center、Skill Package / Center、Agent Builder、Workflow Engine / Studio、Risk Engine、Execution Trace / Versioning 和 Competition Benchmark。**Risk Engine 融入工具调用、审批和执行详情，不是单独的主导航页。**

### 11.1 Tools：工具中心

工具中心统一展示工具名称、版本、参数契约、启用状态、目标、风险、说明和最近使用记录。

当前有 21 项内置工具：

| 工具 ID | 功能 | 主要性质 |
| --- | --- | --- |

| `write_file` | 写入文件，覆盖已有文件时提供备份与原子替换保护 | 变更 |
| `make_directory` | 创建任务目录内的目录 | 变更 |
| `inspect_system` | 查询系统概览、进程、服务或容器 | 读取 |
| `run_command` | 在任务工作目录启动远端命令 | 潜在变更 |
| `http_check` | 从目标主机检查固定范围的回环 HTTP 地址 | 读取/验收 |
| `host_resources` | 查看系统、资源、磁盘与 inode | 读取 |
| `clock_status` | 查看时钟、NTP 与客户端时间差 | 读取 |
| `network_listeners` | 查看监听端口和账号可见的进程归属 | 读取 |

**受控工具包用法：** 选择本地目录 → 预览 manifest、说明、Schema 和完整执行内容 → 安装 → 明确启用 → 新建任务调用。内置工具可以禁用，不能卸载；导入工具可以卸载，历史证据保留。

安装使用预览时缓存的内容，预览十分钟后失效，需要重新审阅。工具包中的远端脚本输出或 HTTP 响应必须符合声明的 JSON 契约；执行失败可能已产生部分变更，不能盲目重试。

工具包支持远端脚本或固定回环 HTTP GET，不加载 Windows 主进程中的第三方 Node 插件。安装后默认禁用；所有导入工具都视为潜在变更，自主模式也逐次审批，不能自称只读或独立验收以绕过限制。v1 更换工具版本需卸载后重新导入，旧会话不会自动采用新版本。

当前本地未发布界面使用同页详情 Inspector，并支持最近使用记录加载失败后刷新重试；正式安装包布局以 v0.4.0 为准。包格式见 [工具包说明](tool-packages.md)。

### 11.2 Skills：技能中心

技能中心管理执行方法、触发场景、工具依赖、约束、风险提示及验收建议。

| 内置技能 | 用途 |
| --- | --- |
| 应用搭建与部署 | 预检、规划、创建项目、部署与业务核验 |
| 故障定位与修复 | 根据状态、日志和实际配置定位根因，最小修复并复核 |
| Linux 环境巡检 | 只读检查资源、时间、端口、服务和容器 |
| 监控无数据排查 | 排查时钟、抓取目标、指标、查询窗口与 Grafana 健康 |

「自动匹配」和「通用任务」是任务选项，不是额外两项内置技能。

**用法：** 在 Skills 查看依赖与说明；导入本地技能目录，预览后安装。安装和升级后默认禁用，补齐并启用必需工具后才能启用技能。在 AI 助手选择自动匹配，或显式选择最多 8 项技能包。

技能包包含 `manifest.json`、`instructions.md` 和 `README.md`，不执行脚本，不引用外部文件。运行保存技能快照；升级或删除定义不改写旧任务。Skill 不能提升权限或替代独立验收。当前本地未发布版本改为同页详情展示，格式见 [技能包说明](skill-packages.md)。

### 11.3 Agents：助手构建

Agent Builder 将模型引用、Tool 白名单、Skill、权限上限、风险策略、服务器范围、目录前缀、预算与验收标准保存为可复用定义。

内置模板包括 **Linux 巡检、Web 服务诊断、应用部署、Compose 运维**。模板需要先绑定「设置」中已有的模型 API，也可以克隆后调整。

**用法：** 编辑或克隆模板 → 绑定模型 → 选择工具和技能 → 设置目标范围、权限和预算 → 保存 → 点击运行并选择服务器、目录与需求。普通运行在 AI 助手会话中处理；绑定默认 Workflow 的运行进入流程记录。

每次保存递增版本，每次运行固定版本与目标快照。定义只引用模型配置 ID，不保存 API Key。支持 JSON 导入/导出；导入生成新 ID 且默认禁用，跨设备引用需要在本机存在。系统模板可禁用不能删除，自定义定义可删除，历史快照保留。

当前本地未发布列表可直接查看模型绑定、权限、风险策略、技能、工具与 Workflow；缺少模型配置或模型 ID 时禁用运行并提示补齐。

Agent 的目标范围与权限约束也作用于其默认 Workflow 和子 Agent。步骤预算按本次运行累计，时间预算包含暂停与审批时间，重启不会重置截止时间。目录前缀只约束任务入口，不是 Shell 沙箱。详见 [Agent Builder 说明](agent-builder.md)。

### 11.4 Workflows：工作流编排

工作流使用节点、连接和持久检查点组织执行。提供 Web 服务故障自愈和应用部署模板；不包含 Agent 节点的普通流程可以不调用模型。

| 节点 | 作用 |
| --- | --- |
| Start | 流程入口 |
| Input | 检查必需输入，缺失时暂停等待补充 |
| Agent | 运行固定快照的子 Agent |
| Skill | 为后续 Agent 加入技能快照 |
| Tool | 调用受控工具 |
| Condition | 按结构化条件选择正常或另一分支 |
| Approval | 审批直接连接的具体 Tool 操作 |
| Verify | 调用合格的内置独立验收工具 |
| Retry | 对已确认失败的指定 Tool/Verify 有限重试 |
| Wait | 等待指定时间并持久保存到期时间 |
| Output | 保存映射后的输出 |
| End | 检查流程是否满足结束条件 |

**用法：** 新建/克隆流程 → 添加和拖动节点 → 编辑右侧属性及连接 → 修改 JSON 后点击「应用节点配置」→ 验证 → 保存 → 运行已保存版本。运行记录中处理审批、输入、暂停、继续、核实及停止；子 Agent 的审批/输入在 AI 助手中处理。

节点映射支持字面值或 `{"$ref":"input.url"}`、`{"$ref":"outputs.status.stdout"}` 这样的结构化引用，不执行任意 JavaScript。普通连接不允许循环；Retry 限 1–3 次，Wait 限 0–300 秒。未知结果不能重试，Retry 不回放整条流程。

审批绑定实际工具、参数、主机、权限、版本摘要与风险，内容变化或重启后需要重新审批。End 拒绝遗留失败或未知节点；有变更时还需要新的 Verify。重启后的流程先核实原作业，已成功节点不重放。默认 1 小时截止时间，最多 300 次节点调度；受父 Agent 约束时取更严格预算。

例如可编排：`Start → Tool（读取状态）→ Condition → Agent（授权修复）→ Verify → Output → End`。该示意需要按实际参数、分支和失败路径配置后验证保存，不能直接当作可运行定义。详见 [Workflow Studio 说明](workflow-studio.md)。

### 11.5 Risk Engine：执行风险

风险引擎在调用前及实际执行入口检查操作，记录分数、等级、因素、规则版本和决定。它与用户权限取更严格限制。

| 等级 | 分数 | 基本含义 |
| --- | --- | --- |
| LOW | 0–20 | 低风险操作 |
| MEDIUM | 21–50 | 中风险操作 |
| HIGH | 51–80 | 高风险操作，均衡策略需要审批 |
| CRITICAL | 81–100 | 拒绝执行，普通审批不能解除 |

谨慎策略要求变更审批；均衡策略要求高风险审批；自主策略在用户选择自主权限后允许非 CRITICAL 操作连续执行，导入工具仍逐次审批。只读权限不会被风险策略升级为写入权限。

**用法：** 在 Agent 配置中选择策略，在实际审批或步骤详情查看风险原因。遇到拒绝应调整操作范围或方案，不能用文字让模型忽略拦截。

当前规则版本为 1.0.2，包含关键路径与符号链接等防护。规则型风险评估不能穷尽 Shell 语义，也不是操作系统隔离。详见 [风险引擎说明](risk-engine.md)。

### 11.6 Runs：执行记录、Trace 与版本

Runs 汇总 Agent、Workflow 及子 Agent 的实际时间线，包括计划、工具调用、风险、审批、模型用量、验收、恢复、目标与版本快照。可跳转子记录，并导出 JSON 或 Markdown。

**用法：** 选择执行记录，查看状态、版本和事件；展开详情核对参数、输出与 Task 引用。需要复盘或分享时使用导出，并检查是否仍有业务敏感信息。

当前本地未发布版本提供紧凑事件表、工具/摘要/Evidence ID 搜索与类型筛选，显示状态、实测耗时和风险；加载失败可刷新，切换记录不会被迟到的旧响应覆盖。Workflow 的重试记录保留每次实际结果，不用最终成功状态覆盖之前失败。

接口未提供的 token、旧记录缺少的版本或耗时保留缺失事实，不估算成实测值。Evidence ID 用于引用记录，本身不是成功证明；成功且符合验收条件的实际结果才可用于交付。详见 [Execution Trace 说明](execution-trace.md)。

### 11.7 Benchmark：真实对照实验

Benchmark 用同一模型及平台安全约束对照三种执行方式：

| 模式 | 组成 |
| --- | --- |
| A | 通用 Agent，不使用 SRE Skill |
| B | SRE Skill 与持久计划 |
| C | 版本化 Agent、Skill、Workflow、Risk、Verify 与恢复 |

共有 12 个场景：Python Web 部署、systemd 服务部署、Compose 部署、ExecStart 路径错误、服务停止、端口冲突、HTTP 500、配置语法错误、SSH 查询连接中断、长任务连续查询失败、后台进程重启、长任务超时核实。

**用法：** 选择专用测试服务器、模型、场景和模式，设置起始端口、步骤及时间上限，选择是否允许已有 sudo。场景 11 的实际应用重启需显式勾选。确认资源与额度后启动，查看每例执行记录和独立验收，最后导出 JSON/CSV/Markdown。

需要审批或输入时可以暂停等待，也可选择按自主执行未完成计分后继续下个样本。暂停只停止后续调度，不撤销当前作业；停止保留资源和证据。

实验会在 `/opt/sre-benchmark/<UUID>` 下创建隔离目录、服务或容器，并消耗模型额度。它是有实际副作用的实验入口，不是演示分数页面。准备失败、接口阻塞和未执行样本单列，不能隐藏；模型声称完成但独立验收失败另计误报。历史结果与统计限制见 [Benchmark 报告](testing/competition-agent-benchmark.md)。

## 12. 设置与本地数据

### 12.1 模型与外部接口

「设置 → 添加 API」可配置名称、类型、地址、模型 ID、API Key/Bearer Token 和超时。类型包括兼容模型 API 与外部 HTTP Agent。

模型接口支持 OpenAI Chat Completions、Anthropic Messages 和自动识别；地址可填写基础地址或完整端点。远端接口使用 HTTPS，本机回环服务可以使用 HTTP。

OpenAI 兼容任务助手要求接口支持 `response_format: {"type":"json_object"}`；Anthropic 兼容任务助手要求支持 `tools` 与指定 `tool_choice`。仅支持普通聊天的网关未必能用于任务执行。

DeepSeek 的 Anthropic 兼容配置可使用 `https://api.deepseek.com/anthropic`，模型 ID 以服务实际支持项为准。历史实测使用过 `deepseek-flash`，不代表其当前可用性、价格或所有账号支持情况。

**用法：** 保存后点击「测试连接」。测试仅发送固定短句，不发送主机日志，可能消耗少量 API 额度；连接成功只证明接口可响应，不证明服务器部署或业务验收成功。模型 API 支持取消和超时，不自动重试请求。

### 12.2 数据保存与备份

配置、版本和执行历史保存在本机 SQLite，凭据使用 Windows safeStorage 加密。数据目录通常是 `%APPDATA%/sre-workbench`。

**备份方法：** 退出软件后备份整个数据目录，避免复制写入中的数据库。凭据绑定 Windows 加密上下文，复制到另一台电脑不代表可直接解密使用。卸载默认保留个人数据。

导出 Agent 定义不包含密钥，Trace 导出会再次脱敏；未知业务秘密仍需要人工检查。不要将数据库、密钥或含敏感内容的备份上传公开仓库。

## 13. 常见使用流程

### 13.1 日常巡检

主机管理检测连接 → 查看资源、服务与端口 → AI 任务助手选择只读诊断及 Linux 巡检 Skill → 提出明确范围 → 查看证据与建议。需要修复时另行选择合适权限，不把只读诊断自动变成变更。

### 13.2 发布已有应用

准备源码 → 创建部署方案 → 校对命令、端口、健康路径及数据目录 → 环境预检 → 确认发布 → 查看任务日志 → 访问应用 → 后续重复发布或回退镜像版本。

### 13.3 配置监控与告警

确认监控服务器到目标 9100 的网络 → 创建方案及阈值 → 设置初始 Grafana 账号和通知 → 部署 → 查看 targets 和 Grafana → 发送测试告警并核实送达。无数据时先检查时间和抓取链路，保留旧数据卷与账号。

### 13.4 将重复故障处理自动化

先人工/只读明确故障和范围 → 配置专用 Agent 的白名单、Skill 与策略 → 编排观测、条件、修复、Verify 和输出 → 保存验证 → 在指定测试主机运行 → 查看 Runs 中的实际证据，再决定是否用于目标业务。

### 13.5 断线后继续任务

找到原 Task/AI 会话/Workflow → 核实原作业 → 根据已有日志和退出码确定结果 → 明确后继续剩余步骤。不要通过重建同一任务掩盖未知状态，也不要清空历史记录后重跑。

## 14. 安全、恢复与能力边界

### 14.1 软件提供的保护

- SSH 指纹信任与目标身份校验。
- 本地凭据加密，模型上下文和导出内容脱敏。
- 后端参数校验、四档权限、白名单、风险评估与具体审批。
- Tool、Skill、Agent、Workflow 运行版本快照。
- 结构化文件工具的目录、真实路径和符号链接边界检查。
- `write_file` 对已有文件提供同目录备份、摘要复核与原子替换保护。
- 持久 Task、检查点及未知状态先核实，避免盲目重放。
- 变更后的独立验收约束与实际执行证据。

### 14.2 使用时必须理解的限制

- 任意 Shell 使用 SSH 账号实际权限，工作目录不是文件系统沙箱。
- Skill 和风险规则不能保证任意模型生成脚本安全、正确。
- 文件工具备份不覆盖 Shell 自行写入、数据库迁移或任意删除；没有通用事务回滚。
- 停止、取消、删除本地记录不等于撤销远端变更。
- 应用版本回退不回退数据库或持久化数据。
- 恢复依赖原作业引用及目标身份，不支持任意脚本内部逐行续跑。
- 文件存在、JSON 语法正确、服务 active、HTTP 2xx 分别只证明对应检查，不等于全部业务正确。
- 实验资源与旧业务要分开管理，不执行全局容器 prune、不删除未知数据卷、不重置旧 Grafana 密码。

### 14.3 当前不包含的能力

没有移动端、Kubernetes、Zabbix 集成、多租户/多人权限、MCP 接入、在线插件市场、通用桌面/浏览器控制或通用数据库迁移与事务回滚。其他发行版、DEB 实机、Windows 重启/完整 Electron 重开、VM 掉电组合及覆盖升级尚未全面验证。安装包未配置商业代码签名。

三个真实 Demo 包括 Web 自愈、Compose 部署/修复和后台进程重启后的子 Agent 恢复。其中 Compose 修复包含一次人工续接；后台重启不等于 Windows 重启。超时场景核实“执行计数 1、结果文件不存在、唯一持久 Task”是正确确认预期超时，不表示业务脚本成功。

以上是已有记录的总结，编写本文没有新增 SSH 或付费模型实验。详细证据以发行验收和 Benchmark 原始数据为准。

### 15.2 技术结构

软件采用 Electron、React、Ant Design 和 TypeScript。受信 IPC 将界面请求交给主进程后端，sql.js SQLite 保存版本化 JSON 与加密凭据。

Agent 与 Workflow 的工具执行统一复用 `ToolRegistry → AgentTools → TaskManager` 的现有链路，长任务在 SSH Linux 主机上使用持久 systemd 作业。受控第三方脚本在 Linux 执行，不作为 Windows 主进程插件加载。

| 目录 | 主要内容 |
| --- | --- |
| `src/main/core` | Backend、Store、SSH、Task 与安全确认 |
| `src/main/features` | 部署、监控、AI、Registry、Builder、Workflow、Risk、Trace、Benchmark |
| `src/shared` | 前后端数据契约 |
| `src/renderer` | 页面、终端、编辑器及交互 |
| `tests` / `tests/e2e` | 单元与 Electron 回归 |
| `examples` | 应用示例和受控 Tool/Skill 包 |

## 16. 常见问题与补充资料

| 问题 | 处理方法 |
| --- | --- |
| SSH 连不上 | 检查地址、端口、网络、账号及凭据；指纹变化先核实身份 |
| 非 root 长任务失败 | 检查用户 systemd/lingering，或按权限明确使用 sudo |
| 部署预检阻塞 | 处理具体磁盘、权限、端口或工具问题，再重新预检 |
| Grafana 没数据 | 核实时钟、9100 可达、Prometheus targets 与指标，再检查面板 |
| 改了 Grafana 初始密码却登不进 | 旧数据卷保留旧账号，应使用原账号在 Grafana 内管理 |
| 模型接口可聊天却不能执行任务 | 核对模型 ID、协议、JSON 输出或工具调用支持，查看具体接口错误 |
| Agent 模板不能运行 | 先绑定本机模型配置，补齐模型 ID 和必需工具/技能依赖 |
| Tool/Skill 导入后不可用 | 安装默认禁用，检查依赖并明确启用；旧会话不自动增加新能力 |
| Workflow 修改后运行仍是旧配置 | 节点 JSON 先应用，再保存，运行采用已保存版本 |
| 断线后结果未知 | 核实原 Task 或恢复会话，不重复提交变更 |
| 模型说成功但结果不对 | 核对最后变更后的 Tool Evidence、Verify 条件和未验证项 |
| 删除方案后服务仍在 | 删除是本地记录操作，远端资源需要单独确认和管理 |
