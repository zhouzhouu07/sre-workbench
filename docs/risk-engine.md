# 风险引擎

Agent与Workflow在Tool调用前使用同一个RiskEngine，ToolRegistry执行入口再次评估，不能绕过。结果包含score、level、factors、action、reason、policy和规则版本，并保存到步骤、工具使用记录及工作流事件。模型不能提供或修改风险上下文。

v0.4.0发行审查后规则版本为1.0.2：文件路径按任务工作目录解析，SSH使用POSIX路径，并同时保留原始拼写参与风险判断。write_file／make_directory在远端realpath之后再次拒绝系统关键路径，防止相对路径、点段或符号链接绕过。两项文件变更工具升级1.0.1，旧快照不会静默更换执行器。既有真实Benchmark产生于Risk1.0.1，原数据保留，不冒充1.0.2实机得分；规则变化的旧实验不能混合版本续跑。

分级：0–20 LOW，21–50 MEDIUM，51–80 HIGH，81–100 CRITICAL。因素集中在src/main/features/risk-engine.ts：Tool基础风险、读写/覆盖、systemd、包管理、容器、删除、防火墙、关键路径、sudo、目标数量、资源影响范围、备份和独立Verify。磁盘覆盖、关键系统路径等至少90分，备份/验收不得降低这类严重风险。第三方声明严重风险同样不能减分变成可执行。

策略取用户权限和风险限制中更严格者：
- 谨慎（Conservative/cautious）：变更必须确认。
- 均衡（Balanced）：高风险需要确认；中低风险仍按原权限决定。
- 自主（Autonomous）：用户明确选择自主权限时允许非CRITICAL范围内连续执行；导入工具仍逐次确认。旧自主会话按此显式授权兼容。
- CRITICAL始终拒绝，普通批准按钮和模型文字不能解除。

新建Agent可显式选择策略；风险策略不能把只读权限提升为写入。UI在操作与审批处展示因素、分数和理由。备份减分仅来自后端收集的同路径成功写入备份标记；不是模型说“已有备份”就采信。Verify规划只有有限减分，真正交付仍要求变更后实际执行独立验收。规则不是终端沙箱，混淆脚本的语义仍可能无法穷尽识别；账号权限、工具白名单、审批与Task恢复机制共同约束执行。
