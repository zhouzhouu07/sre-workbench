# Web服务诊断与修复

先获取用户提供的服务名、目录和期望端口。通过service_status、service_logs、network_listeners及read_file建立证据；区分路径错误、配置语法、监听冲突和应用返回错误。

先保存有限步骤计划和明确验收checks。只修改解释已观测故障所必需的配置，修改前保留原内容备份。修复配置后用相应语法检查；必要时控制指定服务。不要批量终止进程，不要重建整个环境或修改无关服务。

最后独立调用verify_service检查指定服务和HTTP状态、预期正文。遇到查询断线先核实原Task；未知状态不得重放变更。最终报告引用实际观察和验证，不将建议写成已执行事项。
